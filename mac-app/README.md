# ASCII Player

原生 Mac 字符动画播放台，离线使用项目现有的 240 个作品。界面使用 SwiftUI，字符画使用 AppKit / Core Text / Core Graphics 绘制。全部作品均接入本地 C++ 计算库，桌面端已移除 JavaScriptCore。

全部作品已接入具体类型的 C++ 计算实现，计算循环不再通过通用值层执行。每次切入作品独立计时，准备超过 200 ms 并出现“正在准备画面”时，才允许该作品进入缓存。快速作品仅在当前播放期间保留实例，切走后释放。应用在内存中最多缓存 12 个慢作品的实例、最近画面和播放位置，切回时先显示匹配当前单色/彩色及纸色设置的缓存画面，再继续播放。切换仍会取消旧任务；未完成初始化的实例不会入缓存。“从头播放”清除当前作品缓存并重新判断准备耗时。退出应用后缓存释放，超出容量时淘汰最久未使用的慢作品。编译、运行与效果验证由用户执行。

## 打开应用

在项目根目录运行：

```sh
./run.sh
```

脚本会定位项目目录，调用根目录的 `CMakeLists.txt` 配置和增量构建，再打开播放台。CMake 跟踪 C++ 头文件、Swift 源码、字体、图标和打包资源的依赖；没有变化时复用已有产物。若旧版应用仍在运行，先退出旧版应用后再启动。

脚本直接启动应用进程，将构建及应用的标准输出、错误输出同步显示在终端并写入项目根目录 `log.log`，每次运行覆盖旧日志。应用关闭后脚本结束，终端返回命令提示符。作品目录或计算引擎返回的错误也会写入日志；系统崩溃报告仍由 macOS 保存。

构建后的应用位于 `build/ASCII Player.app`，可以直接双击，或拖入「应用程序」文件夹。运行成品无需 Node.js、浏览器或终端。

## 界面

暖白工作台搭配深色播放画布，橙色标记选中项和主要播放操作。左侧按分类搜索与收藏，右侧集中展示作品，底部控制播放。显示设置按外观、画面大小、轮播分组。

界面调整参考 ui-ux-pro-max 的通用规范和 SwiftUI 指南：统一配色、增大正文、按钮交互反馈、无障碍名称与焦点提示。系统启用「减少动态效果」时，打开应用会保持暂停，可手动继续播放。

## 功能

- 按名称、英文描述和中英文分类搜索作品，切换全部作品或收藏。
- 播放、暂停、重新播放、上一幅、下一幅。
- 切回缓存中的作品时恢复播放位置，复用 C++ 实例及最近一帧；首次加载期间暂停播放计时。
- 顺序或随机轮播，切换间隔为 10、20、30、60 或 120 秒。
- 轮播与切换使用当前分类、搜索和收藏筛选后的作品；手动搜索不会打断正在播放的作品。
- 背景、单色模式、字符颜色、三种等宽字体、缩放及帧率上限。
- 全屏、窗口置顶、收起作品库。
- Wave Text 创作预览：编辑文字、振幅、波长、速度、字间距与间歇，调整专属外观，恢复默认。
- 记住收藏、上次播放的作品、窗口位置和显示设置。
- 窗口最小化、应用隐藏和电脑休眠期间停止帧计算；暂停时也暂停轮播计时。

创作第一批支持 Wave Text 参数编辑和预览。点击右上角“创作”或按 ⌘N，右侧打开参数面板。默认参数来自 C++ 作品元数据；文字停止输入 300 ms 后应用，滑块松手后应用，颜色、字体与缩放直接重绘。切换参数会取消旧任务，使用草稿 UUID 和参数修订号创建独立实例。草稿只保留当前预览，播放台的慢作品缓存继续按原规则运行。

进入创作会收起作品库，退出时恢复之前的布局。展示文字使用单行输入框，长内容随光标横向滚动；前后空格和连续空格都会保留。下方提供字符数、空格数、当前间距下的画布容量提示，以及可关闭的空格位置检查（用 `·` 标记，不影响实际文字）。波浪参数直接显示，作品名称及外观设置收在“外观与作品信息”中。

创作期间可暂停、继续和从头播放，轮播及作品切换暂停。点击“返回播放”恢复之前选择的作品；再次进入创作可继续当前草稿。草稿保留到应用退出，写入本地文件、作品库收录及其余模板在后续批次实现。

## 操作

| 快捷键 | 操作 |
| --- | --- |
| 空格 / ⌘P | 播放或暂停 |
| ⌘N | 打开 Wave Text 创作 |
| ← / → | 切换作品 |
| ⌘F | 搜索 |
| ⌘R | 从头播放 |
| ⌘D | 收藏当前作品 |
| ⇧⌘S | 随机选择作品 |
| ⌃⌘F | 全屏 |

播放区获得键盘焦点时，空格与方向键触发播放操作。搜索框、创作输入框及其他控件保留自身的键盘操作；点击画面可将键盘焦点移回播放区。

彩色风景保留自己的底色和调色板；启用单色后使用选定的画布与字符颜色。纸白背景会将默认浅绿色字符自动调成深色。缩放 100% 表示自适应窗口，点击缩放百分比可恢复。

## 本地构建

需要 macOS 14 或更新版本、Xcode 命令行工具及 CMake 3.20+。构建直接编译已经写入 `src-cpp/` 的 C++ 源文件，无需 Node.js、npm 或 Ninja。生成的应用面向构建机器的 CPU 架构。

```sh
cmake -S . -B mac-app/build -DCMAKE_BUILD_TYPE=Release
cmake --build mac-app/build --config Release --target AsciiPlayer --parallel 8
```

在项目根目录执行以上命令，仅构建应用。CMake 为 C++ 引擎生成公共预编译头 PCH，以八路并行编译静态库，再链接 Swift，按依赖生成图标、复制字体与许可证，最后进行本机 ad hoc 签名。保留 `-O3` 优化和构建进度、源文件名、告警与错误输出。首次启用 PCH 时需要重新编译引擎，后续复用已有产物。

新增作品需在 `src-cpp/` 提供实现、元数据和注册入口，再重新构建。只修改原 TypeScript 文件不会自动更新桌面作品。

## 结构

- `Sources/AsciiPlayer/`：原生界面、播放状态、动画引擎与字符绘制。
- `Sources/AsciiPlayer/NativePiece.swift`：导入 C 接口，读取 C++ 目录并拷贝帧数据。
- `Sources/AsciiPlayer/TemplateParameters.swift` / `UserWork.swift`：模板参数、作品身份与专属外观数据，JSON 编解码。
- `Sources/AsciiPlayer/CreationModel.swift` / `CreationPanel.swift`：草稿编辑、合并参数更新与创作面板。
- `../src-cpp/`：240 个作品的计算库；kit 与输出工具独立构建；进度见 `../src-cpp/MIGRATION.md`。
- `scripts/Icon.swift`：生成字符甜甜圈图标。
- `../CMakeLists.txt` / `Info.plist`：构建依赖与应用元信息。
- `build.sh`：原有手动构建脚本；`../run.sh` 使用 CMake 构建。
